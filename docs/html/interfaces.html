Interfaces and simulation

An interface handler is the class that moves telegrams between the interpreter and the vehicle. This page lists the handlers, the strings that select them, and how to run without hardware.

Select a handler

You select a handler in one of two ways:

  • From managed code: create the handler and assign it to EdiabasNet.EdInterfaceClass. The setter also writes the Interface and IfhVersion properties.
  • Through the API shim: set the Interface property in EdiabasLib.config (or pass it in apiInitExt). ApiInternal asks each handler's IsValidInterfaceNameStatic in turn and instantiates the first match. An unknown name raises EDIABAS_IFH_0027.
Interface nameHandlerTransport
STD:OBD, STD:OMITECEdInterfaceObdSerial COM port, FTDI D2XX, Bluetooth SPP or BLE, ELM327, custom Wi-Fi adapters
ADSEdInterfaceAdsADS adapter on a COM port (AdsComPort, falls back to ObdComPort)
EDICEdInterfaceEdicEDIC adapter (EdicComPort)
ENETEdInterfaceEnetHSFZ and DoIP over TCP/IP, BMW ENET cable, ICOM
RPLUS:<name>EdInterfaceRplusRemotePLUS protocol tunneled through an ICOM_P channel

Names are case-insensitive. For RPLUS, the <name> after the colon selects four per-name properties: RemoteHost_<name>, Port_<name>, TimeoutFunction_<name>, and IcomEnetRedirect_<name>. You can also pass the host inline, for example RPLUS:ICOM_P:RemoteHost=192.168.10.20;Port=6801.

Note: A handler reads most of its configuration properties once, when you assign it to EdInterfaceClass. Set the properties first and assign the handler last. See When properties take effect.

STD:OBD

EdInterfaceObd implements the K-Line and D-CAN concepts. It chooses the concept from the communication parameters that the ECU file passes in CommParameter. The following table lists the concepts that the handler accepts under STD:OBD.

Concept numberProtocol
0x0001Concept 1
0x0002Concept 2 (ISO 9141, KWP1281)
0x0003Concept 3
0x0005, 0x0006DS1, DS2
0x010B, 0x010C, 0x010DKWP2000 standard, KWP2000 BMW, KWP2000*
0x010FBMW-FAST
0x0110D-CAN

TP2.0, TP1.6, and ISO-TP (UDS) use concept 0x0000, which only the EDIC handler accepts. Under STD:OBD, that concept raises EDIABAS_IFH_0014. To turn off individual concepts, list their numbers in ObdDisabledConcepts, separated by colons.

The ObdComPort property selects the physical adapter.

ObdComPort valueAdapter
COM4Serial port, including FTDI virtual COM ports on Windows.
FTDI0, FTDI:SER=<serial>FTDI D2XX device by index or by serial number. Used on Android; on Windows use the COM port.
BLUETOOTH:<address>#<pin>Bluetooth SPP (EDR) adapter with the replacement ELM327 firmware.
BLUETOOTH:<address>#BLEBluetooth Low Energy adapter through the GATT serial profile.
BLUETOOTH:<COM port>Bluetooth adapter that is already paired as a serial port. The library opens the port at 115200 baud.
BLUETOOTH:<address>;ELM327Standard ELM327 Bluetooth adapter (Android).
ELM327WIFI[:<ip>[:<port>]]ELM327 Wi-Fi adapter. The default address is 192.168.0.10:35000.

The handler delegates adapter-specific framing to helper classes: EdElmInterface speaks the ELM327 AT command set, EdCustomAdapterCommon speaks the replacement-firmware protocol, and EdBluetoothInterface, EdElmWifiInterface, and EdCustomWiFiInterface own the sockets. Set ObdKeepConnectionOpen to 1 to keep a desktop Bluetooth link or a DEEPOBDWIFI link open between jobs.

ENET

EdInterfaceEnet talks to the vehicle gateway over TCP. It supports two vehicle protocols and picks the first one that answers, in the order given by EnetVehicleProtocol.

ProtocolDefault portsNotes
HSFZDiagnostic 6801, control 6811BMW high-speed fahrzeugzugang. Tester address EnetTesterAddress (default 0xF4).
DoIP13400, TLS on EnetSslPort (default 3496)ISO 13400. Tester address EnetDoIPTesterAddress (default 0x0EF3), gateway EnetDoipGatewayAddress (default 0x0010). The handler uses TLS only when EnetNetworkProtocol is SSL. See DoIP over TLS.

Vehicle discovery

The EnetRemoteHost property controls how the handler finds the gateway. The default is auto.

EnetRemoteHost valueBehavior
autoBroadcasts an identification request to the address in EnetHostIdentService. With the default address, 255.255.255.255, this value behaves like auto:all.
auto:allBroadcasts on every network interface. Prefer this on machines with more than one adapter.
auto:<interface name>Broadcasts on interfaces whose name starts with the given text.
<ip>Connects to the address and tries the protocols in EnetVehicleProtocol order. The host must be an IP address, not a name.
<ip>:HSFZ[:<diagnostic port>[:<control port>]]Connects with HSFZ only. You can omit HSFZ and put the ports right after the address. When you give a port, the handler treats the device as an ICOM.
<ip>:DoIP[:<DoIP port>[:<SSL port>]]Connects with DoIP only. The handler still sends a UDP identification request to the address before it connects.
<ip>:RPLUSConnects with RemotePLUS to an ICOM on port 6801.

DoIP over TLS

Set EnetNetworkProtocol to SSL to run DoIP over TLS on the SSL port. The following properties control the TLS connection:

  • SslBC selects the TLS implementation. With the default, 1, the handler uses the BouncyCastle client in EdBcTlsClient. With 0, it uses the .NET SslStream.
  • SslSecurityPath names the directory with the trusted CA certificates.
  • S29Path names the directory with the client certificates. When you don't set it, the handler uses the S29\Certificates directory next to SslSecurityPath. selectCertificate names the certificate to load.
  • JSONRequestPath and JSONResponsePath name the directories where EdSec4Diag writes certificate requests and imports certificate responses.

ICOM

A BMW ICOM exposes each vehicle channel on its own diagnostic and control port. Use the ports from the ICOM web interface, either in the EnetRemoteHost string or in EnetDiagnosticPort and EnetControlPort.

Set EnetIcomAllocate to 1 to make the library allocate the channel before it connects. The library sends an HTTP request to port 5302 of the ICOM. Allocation runs only on the first connect, not on a reconnect, and only when the connection is an ICOM connection: the EnetRemoteHost string contains ports, the interface is RPLUS, or discovery found an ICOM.

The RPLUS handler reaches the ICOM_P channel through port 6801. When IcomEnetRedirect_<name> is 1 and discovery finds an ICOM at that address with diagnostic port 50160 and control port 50161, the handler switches from RemotePLUS to HSFZ.

The handler contract

A handler derives from EdInterfaceBase, implements its abstract members, and overrides the virtual members that it needs. The following table lists the most important members.

MemberKindPurpose
IsValidInterfaceName(string)AbstractReturns true when the handler accepts the interface name.
InterfaceConnect(), InterfaceDisconnect()VirtualOpen and close the physical link. The base implementation resets the communication parameters, loads or unloads the interface simulation file, and returns true.
InterfaceReset(), InterfaceBoot()AbstractReset the adapter or the ECU link.
TransmitData(byte[] sendData, out byte[] receiveData)AbstractSend one request and receive one response.
TransmitFrequent, ReceiveFrequent, StopFrequentAbstractStart, poll, and stop a repeated request. They back the BEST/1 xsendf, xrequf, and xstopf opcodes.
RawData(byte[] sendData, out byte[] receiveData)AbstractBacks the xraw opcode. Only the RemotePLUS path forwards the bytes. The OBD handler answers a few fixed requests, and the ENET handler returns an empty response.
TransmitCancel(bool)AbstractAbort an in-progress transmission.
CommParameter, CommAnswerLenVirtualCommunication parameters set by the ECU file. They drive baud rate, timing, and concept selection.
KeyBytes, State, BatteryVoltage, IgnitionVoltageAbstractStatus values that the BEST/1 xkeyb, xstate, xbatt, and xignit opcodes return.
Connected, IsEcuConnectedAbstractLink status. The interpreter checks Connected before it calls StopFrequent.
InterfaceLock(int timeout = 0), InterfaceUnlock()VirtualAcquire and release the named system mutex that protects the adapter across processes.

The base class also implements an optional transmit cache, which is off by default. When a host sets EnableTransmitCache to true, TransmitData in the OBD and ENET handlers first looks the request bytes up in the cache. A request that the handler has seen before is answered from the cache, including a cached error code. Setting EnableTransmitCache to false clears the cache.

Simulation mode

Simulation lets you run jobs without a vehicle. Set Simulation to 1 and point SimulationPath at a directory of .sim files. The library looks for two kinds of file:

  • Interface simulation files named after the lower-case interface name, for example enet.sim or obd.sim. The SimulationInterfaces property lists the names to try and accepts wildcards.
  • ECU simulation files named after the lower-case .PRG file, for example d_motor.sim.

A simulation file is an INI file. Each key in the [REQUEST] section maps to a comma-separated list of hex bytes; X matches any nibble. When a request matches, the library returns the entry with the same key from the [RESPONSE] section.

[REQUEST]
key1=83,01,F1,19,02,0C
key2=83,01,F1,22,20,00

[RESPONSE]
key1=83,F1,01,59,02,7F,4F
key2=93,F1,01,62,20,00,01,00,12,28,80,32,80,28,80,31,80,28,01,00,20,28,3E

The parser reads the following sections:

SectionContent
[REQUEST], [RESPONSE]Request and response telegrams, matched by key.
[KEYBYTES]Key bytes that the ECU returns after initialization.
[POWERSUPPLY]UBatt, UBATTCURRENT, and UBATTHISTORY values.
[IGNITION]Ignition, IGNITIONCURRENT, and IGNITIONHISTORY values.
[<hex address>.REQUEST] and similarThe same sections for one ECU address.

EdSimFile parses the file, and EdInterfaceBase.TransmitSimulationData answers requests from it. The extended syntax supports several responses for one request, which lets you simulate an ECU search over functional addressing. For the full syntax, see docs/EdiabasLib.simulation_file.md. The LogfileConverter tool in Tools/ generates simulation files from trace logs.

Note: With SimulationCompat set to 0 (the default), an ECU file that reads the Simulation property gets 0, so its jobs behave as they do on a real vehicle and read every queued response to a functional request. With 1, the ECU file sees the real value.
