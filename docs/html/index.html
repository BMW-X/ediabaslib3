EdiabasLib overview

EdiabasLib is a managed .NET reimplementation of the BMW and VAG EDIABAS diagnostic toolset. It loads ECU description files and runs diagnostic jobs against a vehicle over serial, Bluetooth, USB, or Ethernet.

What EdiabasLib is

EDIABAS is the diagnostic runtime that BMW tools such as Tool32, INPA, and ISTA use to talk to electronic control units (ECUs). ECU behavior is described in .PRG files (one per ECU variant) and .GRP files (group files that identify the variant on the bus). Both file types contain BEST/1 bytecode.

The core library, EdiabasLib.dll, is a BEST/1 virtual machine. It reads the bytecode, executes a named job, sends the telegrams the job produces to the vehicle through a pluggable interface handler, and returns the results as typed result sets. The library emulates EDIABAS version 7.7.2.

Note: This documentation describes the EdiabasLib core project in the Ediabaslib3 fork (branch anykee-v2). The fork adds structured error reporting on top of the upstream uholeschak/ediabaslib project and removes the .NET Framework targets. For every difference and the steps to update existing code, see Fork changes.

Key features

  • Drop-in compatibility. The companion Api32.dll and apiNET32.dll projects expose the original EDIABAS C and .NET ABIs, so existing tools keep working when you replace the DLLs.
  • Multiple transports. D-CAN and K-Line through serial, FTDI, Bluetooth, and Wi-Fi adapters; HSFZ and DoIP over Ethernet, including BMW ICOM and ENET adapters.
  • Protocol coverage. BMW-FAST, D-CAN, KWP2000, KWP2000 BMW, KWP1281, DS1, DS2, ISO 9141, and Concept 1 to 3 through the OBD handler; TP2.0 and ISO-TP through the EDIC handler.
  • Simulation mode. Play back recorded request and response pairs from .sim files without hardware.
  • EDIABAS-compatible traces. The interface trace, ifh.trc, and the API trace, api.trc, use the original format, so you can diff them against a reference EDIABAS installation.
  • Self-contained assembly. A custom build step embeds the NuGet dependencies as resources in the net8.0-windows build, so you can copy a single DLL next to a host application. The other target frameworks need the NuGet assemblies next to the DLL.

Strong namingThe assembly is signed with EdiabasLib.snk, which is checked in. Keep the key so that assemblies compiled against the library continue to bind to it.
ECU filesA directory of .PRG and .GRP files. Set the EcuPath configuration property to that directory.
EncodingECU strings are Windows-1252. Register CodePagesEncodingProvider in your host before you create the first EdiabasNet instance.

Solution layout

Open EdiabasLib/EdiabasLib.sln. The following projects matter most.

ProjectPurpose
EdiabasLibThe interpreter, all interface handlers, transports, simulation engine, TLS for DoIP, and the trace subsystem. This is the project these pages document.
ApiInternalImplements the EDIABAS API functions (apiJob, apiResult*, and so on) on top of EdiabasNet. Selects the interface handler from the Interface property and writes the API trace.
Api32C++/CLI shim that exports the C ABI as Api32.dll or Api64.dll.
apiNET.NET Framework 4.8.1 wrapper that replaces apiNET32.dll.
EdiabasTestConsole harness for running jobs from the command line. See Run a job from the command line.
EdiabasLibConfigToolWinForms tool for adapter setup: Bluetooth pairing, ELM327 firmware, Wi-Fi configuration.
EdiabasLibAndroidNetAndroid build that links most of the same source files plus the *Android.cs variants. Consumed by the Deep OBD app.
Test/Sample callers and the coverage.bat end-to-end script.
Caution: In this fork, only the core library is updated for the new error reporting. ApiInternal, EdiabasTest, and the projects that depend on them don't build yet. See Known issues.
