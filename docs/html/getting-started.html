Get started

This page shows you how to build the library, run a job from C#, and run a job from the command line.

Build the library

You need the .NET SDK 10 or later. Run the following commands from the repository root.

# Build the core library for every target framework
dotnet build EdiabasLib\EdiabasLib\EdiabasLib.csproj -c Release

# Build the core library for a single target framework
dotnet build EdiabasLib\EdiabasLib\EdiabasLib.csproj -c Release -f net8.0-windows10.0.26100.0
Caution: Build the project file, not EdiabasLib.sln. In this fork, ApiInternal and EdiabasTest don't compile, so a build of the whole solution fails. See Known issues.

For the net8.0-windows target, the build embeds the NuGet dependencies (BouncyCastle, Newtonsoft.Json, InTheHand Bluetooth, System.IO.Ports) into EdiabasLib.dll as resources. The custom step lives in Directory.Build.targets. At run time, the static constructor of EdiabasNet loads the embedded assemblies and registers an assembly resolver for them.

Caution: Directory.Build.targets only embeds resources for the net8.0-windows target. Builds for net10.0-windows and net9.0 produce a DLL without embedded dependencies. For those builds, ship the NuGet assemblies next to EdiabasLib.dll; the resolver loads them from that directory.

Api32 is a C++/CLI project and IfhLog is a native C++ project. Build them with MSBuild or Visual Studio, not with dotnet build.

Run a job from C#

Reference EdiabasLib.dll from your project and follow these steps:

  1. Register the code pages encoding provider before you create the first EdiabasNet instance. ECU strings use Windows-1252, and the library requests that encoding when the type loads.
  2. Create an EdiabasNet instance. The constructor reads EDIABAS.INI and EdiabasLib.config from the directory that contains the assembly.
  3. Set the configuration properties that the interface needs, such as EnetRemoteHost or ObdComPort, and set EcuPath.
  4. Assign an interface handler to EdInterfaceClass. The handler reads its configuration properties at this point, so assign it after you set them. The instance takes ownership and disposes the handler with itself.
  5. Call ResolveSgbdFile with a group or ECU file name. For a group file, the library runs the identification job and selects the matching variant.
  6. Set the job arguments and the requested results, and then call ExecuteJob. ExecuteJob clears the arguments when it returns, so set them again before each job.
  7. Read ResultSets. Set 0 holds the system results; sets 1 and later hold the job results.
using System;
using System.Collections.Generic;
using System.Text;
using EdiabasLib;

Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);

using (EdiabasNet ediabas = new EdiabasNet())
{
    // Set the properties first. The handler reads them when you assign it.
    ediabas.SetConfigProperty("EnetRemoteHost", "192.168.10.11");
    ediabas.SetConfigProperty("EcuPath", @"C:\EDIABAS\Ecu");

    // Choose the transport. EdiabasNet disposes it for you.
    ediabas.EdInterfaceClass = new EdInterfaceEnet();

    // Optional callbacks. Set them before the job starts.
    ediabas.ProgressJobFunc = e => Console.WriteLine($"{e.InfoProgressPercent,3}% {e.InfoProgressText}");
    ediabas.AbortJobFunc = () => false;

    try
    {
        // Resolve the group file to the concrete ECU variant.
        ediabas.ResolveSgbdFile("d_motor.grp");

        ediabas.ArgString = string.Empty;                     // job arguments, separated by ';'
        ediabas.ResultsRequests = "STAT_MOTORDREHZAHL_WERT";  // empty string returns all results

        ediabas.ExecuteJob("STATUS_MOTORDREHZAHL");

        List<Dictionary<string, EdiabasNet.ResultData>> sets = ediabas.ResultSets;
        for (int i = 1; i < sets.Count; i++)
        {
            foreach (EdiabasNet.ResultData result in sets[i].Values)
            {
                string text = result.OpData is byte[] data
                    ? BitConverter.ToString(data)
                    : EdiabasNet.FormatResult(result, string.Empty);
                Console.WriteLine($"[{i}] {result.Name} ({result.ResType}) = {text}");
            }
        }
    }
    catch (EdiabasNetException ex)
    {
        // ECU or interpreter error with an EDIABAS error code.
        Console.WriteLine($"{ex.ErrorCode}: {ex.Message}");
    }
    catch (Exception ex)
    {
        // Missing ECU file, transport failure, or abort.
        Console.WriteLine(ex.Message);
    }
}
Note: Pass string.Empty, not null, as the format to FormatResult. The method returns null for binary results, which is why the example converts byte[] values itself.

Job arguments

EDIABAS jobs accept either a string argument list or a binary argument. Set one of the following properties before you call ExecuteJob:

PropertyUse
ArgStringSemicolon-separated string arguments, for example "0x4232;1".
ArgBinaryRaw bytes. EdiabasNet.HexToByteArray("A3C2") converts a hex string. ArgString and ArgBinary share one buffer, so set only one of them.
ArgStringStd, ArgBinaryStdArguments for the standard jobs (INITIALISIERUNG, IDENTIFIKATION, and the exit job) that the library runs on your behalf.
ResultsRequestsSemicolon-separated names of the results you want. An empty string requests every result. Don't assign null.

Configure without a config file

The constructor accepts an optional configuration string. Use either an inline list of properties or a path to a config file prefixed with @.

// Inline properties override EdiabasLib.config values.
var ediabas = new EdiabasNet("EnetRemoteHost=auto:all;IfhTrace=2");

// Load a specific config file instead of the one next to the assembly.
var hosted = new EdiabasNet(@"@C:\MyApp\EdiabasLib.config", isHosted: true);

Set isHosted to true when the library runs inside a service or another host that manages its own trace directory. The constructor then skips the automatic creation of a Trace folder next to the assembly.

Run a job from the command line

The EdiabasTest console application runs jobs against ECU files without any code.

Warning: EdiabasTest doesn't build in this fork, because it targets .NET Framework 4.8.1 and the fork removed that target from the library. To use the commands in this section, build EdiabasTest from the upstream project, or retarget it first. See Known issues.

The general form of a job argument is:

<job name>#<arguments ; separated>#<requested results ; separated>#<standard arguments ; separated>

Prefix a binary argument with |, for example |A3C2.

EdiabasTest.exe -p "COM4" --cfg="IfhTrace=2" -s "Ecu\d_motor.grp" ^
    -j "FS_LESEN" ^
    -j "FS_LESEN_DETAIL#0x4232#F_ART_ANZ;F_UW_ANZ" ^
    -j "STATUS_RAILDRUCK_IST##STAT_RAILDRUCK_IST_WERT"
FlagMeaning
-s, --sgbd=Group or ECU file to load.
-p, --port=COM port for the OBD, ADS, and EDIC interfaces. For the ENET interface, the remote host.
--ifh=Interface handler: STD:OBD, STD:OMITEC, ADS, EDIC, ENET, or RPLUS:<name>.
--cfg=Semicolon-separated property overrides, for example --cfg="IfhTrace=3;EnetRemoteHost=auto:all".
-j, --job=A job to run. Repeat the flag to run several jobs in order.
-f, --format=Format string for one result, for example -f STAT_TEMP_WERT=-8.2R. See FormatResult.
-o, --out=Write output to a file instead of the console. Add -a to append to the file.
--continueContinue with the next job after an error.

Verify the setup

Run one job with tracing enabled and inspect the trace file. Set IfhTrace to 1 to log the interface events and every telegram, or to 3 to also log each BEST/1 opcode that the interpreter executes. The library writes ifh.trc to the directory that the TracePath property names. See Tracing.
