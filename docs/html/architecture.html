Architecture

EdiabasLib has three layers: an optional binary-compatible API shim, the BEST/1 interpreter, and a family of interface handlers that move telegrams to and from the vehicle.

API shim

The Api32 project is a C++/CLI assembly that exports the EDIABAS C functions. It forwards every call to ApiInternal, which owns one EdiabasNet per API handle and maps the C-style result access functions (apiResultText, apiResultInt, and so on) onto the result sets. When a host uses the shim, the Interface configuration property decides which handler ApiInternal creates. Managed hosts that reference EdiabasLib.dll directly skip this layer and assign EdInterfaceClass themselves.

Interpreter

EdiabasNet is a partial class split across two files:

  • EdiabasNet.cs holds the data structures, configuration, file loading, group resolution, the execution loop, registers and flags, result-set assembly, and the trace writers.
  • EdOperations.cs holds a static method for each implemented BEST/1 opcode, for example OpA2Fix, OpTabsetex, and OpXstopf. The dispatcher in EdiabasNet.cs looks the handler up in an opcode table and passes the operand descriptors. An opcode without a handler throws ArgumentOutOfRangeException with the text Function not implemented.

Values inside the VM use the aliases EdValueType (UInt32) and EdFloatType (Double). The library emulates EDIABAS 7.7.2, and the opcodes always use the behavior of that version. The one run-time switch is the CompatMode property, which only affects the a2flt opcode: with 0, an invalid floating-point string raises EDIABAS_BIP_0011; with the default, 1, it doesn't.

Interface handlers

Every transport derives from EdInterfaceBase. The interpreter talks to the handler through the members that the base class declares, such as TransmitData, TransmitFrequent, ReceiveFrequent, StopFrequent, RawData, CommParameter, KeyBytes, and the status properties. The base class provides the simulation hooks, an optional transmit cache, and BMW-FAST helpers. See Interfaces and simulation.

How a job runs

  1. Resolve the ECU file. ResolveSgbdFile(name) calls GetFileType to classify the file. For a .PRG file, it stores the name in SgbdFileName. For a .GRP file, it runs the group's IDENTIFIKATION job through the interface, reads the VARIANTE result, stores the matching .PRG name, and sets GroupName and FamilyName. Resolved groups are cached per instance; ClearGroupMapping() clears the cache.
  2. Open the file. On the first ExecuteJob after a file name change, the interpreter opens the .PRG file with MemoryStreamReader, which memory-maps it on desktop builds, and reads the list of base files, the version information, the job list, and the table list. If the file can't be opened, ExecuteJob throws ArgumentOutOfRangeException.
  3. Run the initialization job. After each file open, the interpreter runs INITIALISIERUNG before the job you asked for. The job is mandatory: a file without it raises EDIABAS_SYS_0008, and an initialization job that doesn't report DONE as 1 raises EDIABAS_SYS_0010. Standard jobs read ArgStringStd and ArgBinaryStd instead of the user arguments.
  4. Execute the job. ExecuteJobPrivate looks the job up in the job list and raises EDIABAS_SYS_0008 when it's missing. It resets the flags, the string registers, the stack, and the error trap state, and then loops over the bytecode. Each opcode reads its operands through the address-mode decoder and calls the handler in EdOperations.cs. Opcodes that talk to the ECU (xsend, xrequf, xstopf, and others) call the interface handler.
  5. Collect results. The result opcodes (ergb, ergw, ergd, ergi, ergr, ergs, ergy, and others) add typed values to the current result set, and enewset closes the set. The job itself skips the results you didn't ask for: its etag opcode checks each result name against ResultsRequests.
  6. Assemble the result list. When the job ends, the interpreter builds the system result set, inserts it at index 0, and publishes the new list through ResultSets. It then clears the job arguments.

Result set layout

ResultSets is a List<Dictionary<string, ResultData>>. Index 0 is the system set, which mirrors the EDIABAS system results.

System resultTypeMeaning
VARIANTETypeSUpper-case ECU file name without extension.
GRUPPE, FAMILIETypeSLower-case group and family names. Empty when you resolve a .PRG file directly.
OBJECTTypeSName of the object that provides the job (the file itself or a base file).
JOBNAMETypeSName of the executed job.
SAETZETypeWNumber of job result sets (excluding the system set).
JOBSTATUSTypeSStatus string set by the job. Present when SystemResults isn't 0, which is the default.
UBATTCURRENT, UBATTHISTORY, IGNITIONCURRENT, IGNITIONHISTORYTypeIBattery and ignition state. Present when SystemResults isn't 0. The values are -1 unless the job runs in simulation mode.

Sets 1 through SAETZE hold the job results. Each ResultData carries the result name, a ResultType, and the boxed value in OpData. Integer types box as Int64, TypeR as Double, TypeS as string, and TypeY as byte[].

Threading model

  • One EdiabasNet instance runs one job at a time. ExecuteJob throws ArgumentOutOfRangeException when JobRunning is true.
  • The following setters also throw while a job runs: ArgString, ArgBinary, ArgStringStd, ArgBinaryStd, SgbdFileName, EdInterfaceClass, AbortJobFunc, ProgressJobFunc, and ErrorRaisedFunc. SetConfigProperty throws for EcuPath, Simulation, and SimulationPath.
  • To abort a job from another thread, set AbortJobFunc before the job starts and have the delegate read a flag that the other thread sets.
  • Property reads are guarded by a private lock, so another thread can read InfoProgressPercent or JobRunning while a job runs.
  • The library doesn't lock the adapter by itself. InterfaceLock acquires a named system mutex, one per handler class, and only ApiInternal calls it. A host that references the library directly and shares an adapter between processes must call InterfaceLock and InterfaceUnlock itself.
  • A few caches are static and shared across instances: the error trap bit table, the shared data dictionary, and the embedded assembly loader. The library counts live instances and clears the shared data when the last instance is disposed.

Ownership and disposal

EdiabasNet implements IDisposable. Dispose closes the ECU file and any open table or user files, disposes the interface handler assigned to EdInterfaceClass, and then closes the trace writers. Assign a fresh handler to each instance. Don't share one handler between instances.

Conditional compilation

Most source files build into both the desktop library and the Android library. The code branches on the following symbols.

SymbolDefined byEffect
ANDROIDThe .NET Android SDKUses android.util.Log, the Android Bluetooth and FTDI drivers, and skips desktop file IO.
USE_SERIAL_PORT#if !ANDROID at the top of EdInterfaceObd.csEnables the System.IO.Ports path.
BLUETOOTHDirectory.Build.targetsEnables desktop Bluetooth SPP and BLE code in EdBluetoothInterface.cs.
COMPRESS_TRACEAndroid buildsAdds the CompressTrace property. When the property isn't 0, the library writes the trace into a ZIP archive.
Note: When you change a file that contains #if ANDROID, build EdiabasLibAndroidNet as well. The desktop build doesn't compile the Android branches.
