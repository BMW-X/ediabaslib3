Configuration

EdiabasLib stores every setting as a named string property. You can set properties from files, from the constructor, or from code at run time.

Where settings come from

The EdiabasNet constructor applies settings in the following order. Later sources override earlier ones.

  1. Built-in defaults. The constructor sets EcuPath to the assembly directory, ApiTrace and IfhTrace to 0, and computes a default TracePath.
  2. EDIABAS.INI in the assembly directory, if present. The constructor reads only the Interface, EcuPath, ApiTrace, IfhTrace, and TraceBuffering keys from the [Configuration] section.
  3. EdiabasLib.config in the assembly directory, or the file that you name with an @ prefix in the constructor argument. Every <add key="..." value="..."/> element under <appSettings> becomes a property.
  4. The constructor string. A semicolon-separated key=value list, for example "EnetRemoteHost=auto:all;IfhTrace=2". The constructor argument is either this list or an @ file name, not both.
  5. Code. SetConfigProperty(name, value). Pass null or an empty string to remove a property.

Property names are case-insensitive. GetConfigProperty(name) returns null for an unknown name, so check for null before you parse a value.

Note: The ENET handler also reads the [XEthernet] and [SSL] sections of EDIABAS.INI, but only when its configured remote host isn't an IP address (for example, the default auto) and the RemoteHost key in the file is one. Put the rest of your settings in EdiabasLib.config.

When properties take effect

The library doesn't read every property at the same time. The following table shows when a change takes effect.

PropertiesWhen the library reads them
Interface handler properties: ObdComPort and the other Obd* properties, AdsComPort, EdicComPort, the Enet* properties, and the per-name RPLUS propertiesOnce, when you assign the handler to EdInterfaceClass. A later call to SetConfigProperty has no effect on the handler.
RetryComm, ObdKeepConnectionOpen, SimulationInterfaces, SystemResults, and the trace propertiesEach time the library uses them.
EcuPath, Simulation, SimulationPathImmediately. SetConfigProperty throws ArgumentOutOfRangeException for these three properties while a job runs.

To change a handler setting after you assign the handler, use the public properties of the handler instead, for example EdInterfaceObd.ComPort or EdInterfaceEnet.RemoteHost.

Sample EdiabasLib.config

<?xml version="1.0" encoding="utf-8" ?>
<configuration>
  <appSettings>
    <add key="Interface" value="ENET"/>
    <add key="EcuPath" value="C:\EDIABAS\Ecu"/>
    <add key="EnetRemoteHost" value="auto:all"/>
    <add key="ObdComPort" value="COM4"/>
    <add key="ApiTrace" value="0"/>
    <add key="IfhTrace" value="0"/>
    <add key="LockTrace" value="0"/>
  </appSettings>
</configuration>

The constructor also sets UbattHandling, IgnitionHandling, ClampHandling, BipDebugLevel, TaskPriority, and EdicApiHandle to 0 so that ECU files that read them get a value. The library forwards UbattHandling and IgnitionHandling to an ICOM over RemotePLUS and doesn't use the others.

RPLUS properties

The RPLUS handler reads four properties whose names end with the channel name from the interface string. For the interface RPLUS:ICOM_P, the names end with _ICOM_P.

PropertyDefaultDescription
RemoteHost_<name>NoneIP address of the ICOM.
Port_<name>6801RemotePLUS port.
TimeoutFunction_<name>15000Timeout in milliseconds for each RemotePLUS function call.
IcomEnetRedirect_<name>See description1 lets the handler switch from RemotePLUS to HSFZ when the ICOM offers HSFZ on its standard ports. Set the property explicitly to turn the redirect on.
