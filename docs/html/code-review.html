Code review

Review of the EdiabasLib core project on branch anykee-v2 (commit 8c2f61c4a), with a focus on the two fork commits and on the way the AnyKee WsHub service consumes the library.

Summary

The library is a mature, feature-complete EDIABAS reimplementation with careful protocol timing, invariant-culture handling, and an EDIABAS-compatible trace format. The main risks are structural: transport state is shared through static fields, the solution no longer builds end to end after the fork's .NET Framework removal, and there is no automated test coverage. Two findings affect the WsHub service directly and have one-line fixes on the WsHub side.

SeverityCountMeaning
Critical6Build break, data corruption between instances, or a process crash from external input.
High10Resource leaks, security weaknesses, or silent wrong behavior in supported scenarios.
Medium22Bugs on edge paths, contract violations, or maintainability problems with real cost.
Low6 groupsCleanups, naming, dead code, and minor inconsistencies, grouped per area.

Do these first

  1. Fix the build. Update the two remaining references to the nested EdiabasNet.EdiabasNetException in ApiInternal.cs and EdiabasTest/Program.cs, and retarget the net481 projects. Right now Api32, apiNET, and EdiabasTest cannot compile. See F1.
  2. In WsHub, create the ENET handler with new EdInterfaceEnet(shared: false). The default constructor shares one TCP connection across every instance in the process, and the job queue runs jobs in parallel. See E1.
  3. In WsHub, pass plain port numbers. EnetDiagnosticPort and EnetControlPort currently receive "<ip>:50160", which parses as port 192. See E8.
  4. Embed dependencies for net10.0-windows. The flagship target ships a 463 KB DLL with no embedded NuGet assemblies. See C3.
  5. Keep the old SetError and RaiseError overloads. The new optional parameters break binary compatibility for every prebuilt consumer. See F3.
  6. Guard the ELM327 receive thread. A malformed first frame from the adapter crashes the process. See O1.

Fork changes

The fork adds two commits: 2a6186bc8 (error handling refactor, .NET 4.x removal, dependency cleanup) and 8c2f61c4a (xstopf no-op on a closed channel). The direction is right; the execution leaves the solution inconsistent.

F1. Solution no longer compiles Critical

ApiInternal/ApiInternal.cs:1447, EdiabasTest/Program.cs:280, EdiabasTest/EdiabasTest.csproj:6, apiNET/apiNET464.csproj:5, Test/EdiabasLibCall/EdiabasLibCall.csproj:6

Both files still pattern-match on EdiabasNet.EdiabasNetException, which the fork commented out. dotnet build ApiInternal.csproj fails with CS0426. In addition, EdiabasTest, apiNET464, and EdiabasLibCall target net481 and reference projects that no longer expose a .NET Framework target, so NuGet reports NU1201. The last built ApiInternal.dll predates the fork commit, and coverage.bat still points at bin\Debug\net481.

Fix: replace both references with EdiabasNetException, retarget EdiabasTest to net10.0-windows10.0.26100.0, decide whether apiNET464 and EdiabasLibCall keep a Framework target (they only make sense against the original apiNET32.dll), and add a CI step that builds the whole solution.

F2. Exception constructor without an error code reports success High

EdiabasLib/EdiabasNetException.cs:11-17

EdiabasNetException(string message, Exception inner = null) leaves ErrorCode at EDIABAS_ERR_NONE and HResult at the default. ApiInternal converts ErrorCode to the API error, so a caller sees 0, which means success. The constructor is unused today, so it is a trap rather than a live bug. The fallback message ?? errorCode.ToString() in the other constructor never triggers because GetErrorDescription returns an empty string, not null, for unknown codes.

Fix: remove the code-less constructor or make it use EDIABAS_SYS_0000; use string.IsNullOrEmpty(message) for the fallback.

F3. New optional parameters break binary compatibility High

EdiabasLib/EdiabasNet.cs:4141, 4175

SetError(ErrorCodes) and RaiseError(ErrorCodes) no longer exist as separate overloads. Optional parameters are filled in by the caller's compiler, so any assembly compiled against the previous EdiabasLib.dll (Deep OBD, third-party interface handlers, older ApiInternal builds) throws MissingMethodException at run time. This defeats the strong-named drop-in goal.

Fix: keep forwarding overloads:

public void SetError(ErrorCodes error) => SetError(error, null, null);
public void RaiseError(ErrorCodes error) => RaiseError(error, null, null);

[CallerMemberName] works as intended and yields values such as OpTabsetex or TransmitData, but the member name alone is ambiguous across handlers and it overwrites the documented meaning of Exception.Source. Prefer a dedicated Member property on the exception, or add [CallerFilePath].

F4. Rethrow policy is now inconsistent across the execute paths Medium

EdiabasLib/EdiabasNet.cs:5578-5584, 5876-5882 (changed); 5545-5551, 5704-5723, 5916-5924, 6973-6980 (unchanged)

The job and identification paths now rethrow every exception unchanged, which is the better policy, but the exit job, base job, virtual job, and operand decoder still wrap failures in new Exception(...). Aborts are still signaled by new Exception("executeJob aborted"), and Deep OBD matches that string. The //at// maybe original code will work comments leave the intent unclear.

Fix: apply the rethrow policy to all six sites, throw OperationCanceledException for aborts, and document the contract on ExecuteJob.

F5. The xstopf no-op treats a symptom Medium

EdiabasLib/EdOperations.cs:3227-3236; EdiabasNet.cs:3961-3969

Every sibling opcode (xsend, xsendf, xtype, xvers) still raises EDIABAS_IFH_0056 for a missing channel, so trace diffs against reference EDIABAS now differ for this opcode only. The real problem is that CloseSgbdFs runs the exit job without a try block, so an ENDE job that calls stop_frequent after the link dropped fails the next job on a different ECU file.

Fix: keep IFH_0056 for a null interface, wrap ExecuteExitJob in CloseSgbdFs with a logged catch, and log the no-op at Ifh level so traces explain the missing error.

F6. Formatting debris Low

EdiabasNet.cs:1518-1526, 4140-4202, 5578-5584, 5876-5882; EdOperations.cs:2616-2641; EdiabasNetException.cs:7

The fork introduced tab-indented lines into space-indented files, left the old nested class and old calls as comments, and added seven //at// markers. The argument keys passed to SetError differ between the two OpTabsetex sites (filename is the .prg candidate at one site and the full path at the other).

Fix: run the formatter, delete commented code, and define the argument keys as constants.

Interpreter core

Files: EdiabasNet.cs, EdOperations.cs, EdiabasLib.csproj, Directory.Build.targets.

C1. Static register table is rebound to the last constructed instance Critical

EdiabasNet.cs:1597, 1866, 3227, 6985-7007

RegisterList is static readonly, each Register holds a reference to one EdiabasNet, and every constructor calls SetEdiabas(this) on all of them. Every opcode operand resolves registers through this table, so with two live instances in one process, the first instance reads and writes the second instance's registers. Multi-instance use is explicitly supported (instance counter, one instance per API handle). This is inherited from upstream and is the most serious defect in the core.

Fix: build the register array per instance in the constructor and make GetRegister an instance method.

C2. Check-then-act on JobRunning is not atomic Medium

EdiabasNet.cs:5739-5745, 5340-5344, 2579-2594

The getter and setter each take the lock separately, so two threads can both pass the if (JobRunning) check and run the VM concurrently on shared registers and result dictionaries.

Fix: Interlocked.CompareExchange on an int field, or test and set inside one lock.

C3. net10.0-windows and net9.0 builds embed no dependencies High

Directory.Build.targets:13-25; EdiabasLib.csproj:5

Only the net8.0-windows group embeds NuGet DLLs. The built net10.0-windows DLL is 463 KB with no manifest resources, against 6.27 MB for net8. LoadAllResourceAssemblies returns false and the resolver falls back to loading from the assembly directory, so a drop-in of a single DLL fails at first use of Newtonsoft, BouncyCastle, or System.IO.Ports. The net8 group also references a net8.0-windows10.0.19041 folder for InTheHand.BluetoothLE 4.0.44 that does not exist, so the wildcard matches nothing. The net48 group is dead and references a deleted binary.

Fix: add groups for net10 and net9 mirroring net8 with the correct package folders (InTheHand.BluetoothLE\lib\net9.0-windows10.0.19041, System.IO.Ports\lib\net10.0), delete the net48 group.

C4. net9.0 target is neither Windows nor cross-platform High

EdiabasLib.csproj:26-29; Directory.Build.targets:3; EdSec4Diag.cs:270, 283

net9.0 has no -windows suffix, yet BLUETOOTH is defined unconditionally, so EdBluetoothInterface compiles against the packages' non-Windows stub assemblies, and EdSec4Diag calls Microsoft.Win32.Registry, which throws off Windows. Windows hosts on .NET 9 get no net9.0-windows build.

Fix: decide the purpose. For Linux support, gate BLUETOOTH on $(TargetFramework.Contains('-windows')) and guard registry calls with OperatingSystem.IsWindows(). For Windows hosts, rename to net9.0-windows10.0.26100.0 and extend the conditions.

C5. Unsynchronized static mutable state Medium

EdiabasNet.cs:2437, 2441, 2445, 2492, 3177-3213

_trapBitDict is built lazily in the constructor with no lock and is assigned before the last Add calls, so a concurrent constructor can observe a dictionary mid-mutation. _timeMeas is static but exposed through the instance property TimeMeas and updated with += from OpXsend. _instanceCount is incremented before the constructor can throw, so a failed construction leaks the count and SharedDataDict is never cleared.

Fix: make the trap table static readonly with an eager initializer, make _timeMeas an instance field, and increment the counter at the end of the constructor.

C6. Code page 1252 requires the host to register a provider Medium

EdiabasNet.cs:2434

The static initializer calls Encoding.GetEncoding(1252). On .NET 8 and later this throws unless CodePagesEncodingProvider is registered. Only EdiabasTest, the config tool, and one sample do so; ApiInternal does not, so a native host loading Api32.dll gets a TypeInitializationException. The .NET Framework targets masked this until the fork removed them.

Fix: register the provider in a static constructor or module initializer inside the library.

C7. Trace append window uses TimeSpan.Hours Medium

EdiabasNet.cs:6626

diffTime.Hours is the component (0 to 23), not the total. A trace last written 25 hours ago has Hours == 1 and is appended to; 1 hour 59 minutes also passes.

Fix: diffTime.TotalHours > TraceAppendDiffHours.

C8. wait and waitex overflow Medium

EdOperations.cs:3278, 3284

(int)(value * 1000) wraps for UInt32 values at or above 4,294,967 and yields a negative sleep for results at or above 2^31, which throws or, for -1, sleeps forever. Long waits also ignore AbortJobFunc.

Fix: compute in long, clamp to int.MaxValue, and sleep in chunks that poll the abort delegate.

C9. State errors are thrown as ArgumentOutOfRangeException Low

EdiabasNet.cs:2614, 2644, 2674, 2704, 2883, 2905, 2927, 2995, 3070, 5343, 5448-5475, 5663, 5722, 5741, 5821, 5863

"Job is running", "open SGBD failed", and "file not found" are InvalidOperationException, InvalidDataException, and FileNotFoundException situations. GetFileType passes the file name as the parameter name, which produces misleading messages.

C10. Minor core issues Low

  • EdiabasNet.cs:5668 logs {0:X08} twice; the second placeholder should be {1:X08}. Traces are diffed against EDIABAS, so this matters.
  • EdiabasNetException.cs:22 sets HResult to a positive value, which is a success HRESULT if the exception ever crosses a COM boundary. Encode as unchecked((int)0xA0000000 | code) or document it as informational.
  • EdiabasNet.cs:5627-5652 builds the argument log string on every job regardless of trace level.
  • ResultSets and ResultsRequestDict return the live mutable collections; SetError mutates trap state outside the lock that ErrorCodeLast reads under.
  • Dispose disposes the caller-injected interface handler without documenting ownership and does not check JobRunning.
  • FormatResult(result, null) throws from Regex.Replace; accept null as empty.

ENET transport

Files: EdInterfaceEnet.cs, EdInterfaceRplus.cs, TcpClientWithTimeout.cs, EdBcTlsClient.cs, EdBcTlsUtilities.cs, EdSec4Diag.cs, EdWebServer.cs. This is the transport WsHub uses.

E1. All EdInterfaceEnet instances share one connection by default Critical

EdInterfaceEnet.cs:765, 829-835, 1692-1697, 1736; AnyKee.WsHub.Core/Jobs/EdiabasJob.cs:1430; BackgroundServices/JobQueueProcessor.cs:333

SharedDataStatic holds the TCP client, stream, receive queue, events, host connection, and TLS state. The constructor default is shared = true, and InterfaceConnect returns true without connecting when the shared client already exists. WsHub creates a new handler per job with the default and runs jobs through an ActionBlock with MaxDegreeOfParallelism greater than one. A second concurrent job sends its telegrams down the first job's socket and both dequeue from the same receive queue. Even with one job at a time, the finalizer of an undisposed instance disconnects the live instance's socket.

Fix (WsHub, one line): ediabas.EdInterfaceClass = new EdInterfaceEnet(shared: false);. Fix (library): make non-shared the default, or remove SharedDataStatic and document that sharing exists only for the single-connection Android app.

E2. TcpClient leaks on connect timeout High

TcpClientWithTimeout.cs:70, 88-112

ConnectAsync runs without a token; on timeout or cancel the method throws and never disposes the client, and callers never receive it. A dedicated thread is started per connect when a cancel event is passed. With RetryComm=3 a dead ICOM leaks several sockets per failed job in a long-lived service.

Fix: use ConnectAsync(host, port, token), wait with the timeout, and dispose the client in a catch.

E3. Receive pump does not handle EOF and swallows exceptions High

EdInterfaceEnet.cs:4700-4725

When the peer closes the connection, EndRead returns 0, the pump re-arms BeginRead, and a thread-pool thread spins until the next acknowledgement timeout forces a reconnect. The catch logs nothing and does not set ReconnectRequired, so Connected stays true with no reader. ICOM devices drop idle connections, so this shows up as CPU burn and delayed failure detection in WsHub.

Fix: on recLen <= 0 or exception, log, set ReconnectRequired, signal the receive event, and stop reading.

E4. BouncyCastle TLS path validates the server certificate by issuer name only High

EdBcTlsClient.cs:226-231; EdBcTlsUtilities.cs:429-462

CheckCertificateChainCa returns true when any certificate in the chain has an issuer name equivalent to a trusted CA subject. There is no signature verification, validity check, or path building. The BouncyCastle path is the default. A gateway presenting any self-signed certificate with the BMW CA's distinguished name as issuer is accepted. The SslStream path builds a real chain.

Fix: reuse the existing ValidateCertChain (PKIX path validation) in NotifyServerCertificate, or at minimum verify the top certificate's signature with the CA public key.

E5. Compounding, non-cancellable timeouts on the caller thread High

EdInterfaceEnet.cs:2424, 5071-5127, 5670-5692, 1747, 1481-1558, 7427

TransmitData retries up to four times with RetryComm=3; each attempt can wait 10 seconds for an acknowledgement, reconnect with a 5 second timeout, and resend. A dead gateway pins a thread-pool thread for tens of seconds to over a minute per call. InterfaceConnect resets the cancel event even on reconnect, so a cancel during reconnect is lost. IgnitionVoltage is a property getter that opens a TCP control connection and blocks.

Fix: thread a deadline or CancellationToken through InterfaceConnect and TransmitData, keep the cancel event set across reconnects, and expose ignition reading as a method.

E6. Receive callbacks call InterfaceDisconnect with no synchronization Medium

EdInterfaceEnet.cs:4817-4837, 4943-5063, 2320-2324, 5221

The DoIP and NMP receivers tear down the connection from the callback thread while the transmit thread may be inside SendDoIpData or InterfaceConnect. Cross-thread fields are not volatile, and DoIpRoutingState is read outside the lock that writes it.

Fix: receivers only flag ReconnectRequired and signal; the transmit thread performs the reconnect.

E7. Finalizer performs network and managed work Medium

EdInterfaceEnet.cs:1687-1690, 7674-7679; EdInterfaceObd.cs:1315-1318, 5713-5732

Both handlers define a finalizer that calls Dispose(false), and Dispose(bool) calls InterfaceDisconnect before checking disposing. That path logs through the interpreter, may run network I/O, waits up to 3 seconds on an event, releases a mutex from a thread that does not own it, and touches static shared state. Neither class owns unmanaged resources.

Fix: delete the finalizers and move the disconnect under if (disposing).

E8. Port properties are not validated, and WsHub passes host:port strings Medium

EdInterfaceEnet.cs:948-994; EdiabasNet.cs:7252-7257; AnyKee.WsHub.Core/Jobs/EdiabasJob.cs:1426-1427

StringToValue cuts decimal input at the first . or ,, so "192.168.1.5:50160" becomes 192. WsHub sets EnetDiagnosticPort and EnetControlPort to exactly that form. Diagnostics work only because EnetRemoteHost carries the diagnostic port and overrides it, but the control port is 192, so ignition-state reads through the control channel always fail and the UDP port filter is wrong.

Fix (WsHub): pass "50160" and "50161", or use EnetRemoteHost = "<ip>:50160:50161". Fix (library): validate the range 1 to 65535 and raise EDIABAS_IFH_0041 otherwise.

E9. Oversized frames desynchronize the stream instead of reconnecting Medium

EdInterfaceEnet.cs:4782-4786, 4908-4912, 5049-5053, 5951-5977

When an advertised length exceeds the buffer, the code drains only the currently available bytes. The rest of the frame arrives later and is parsed as a new header. For the BouncyCastle TLS stream the drain is a no-op, and for SslStream the 1 ms read timeout throws before the timeout is restored.

Fix: treat it like the DoIP version check: log, set ReconnectRequired, stop reading.

E10. ICOM allocation over HTTP Medium

EdInterfaceEnet.cs:3553-3583, 2114, 2356, 7712-7716

The user agent is appended to the long-lived HttpClient on every call, the continuation blocks with .Result, it is registered with the timeout token so a cancel silently drops it, and the handler sets IcomEvent after Dispose, which throws ObjectDisposedException as an unobserved task exception. Only active when EnetIcomAllocate=1.

E11. Secrets and weak randomness in EdSec4Diag Medium

EdSec4Diag.cs:30, 31, 209; EdInterfaceEnet.cs:4152-4156

A PKCS#12 password is a public const exported from the library; certificate serial numbers come from System.Random; RoleMask is a mutable public static array; the machine certificate's .p12 password is derived from the machine name, so the private key on disk is effectively unprotected; registry writes compile into the non-Windows target.

Fix: move the password to the tool that needs it, use SecureRandom, make RoleMask read-only, guard registry code with OperatingSystem.IsWindows().

E12. EdWebServer is an open control endpoint that cannot be stopped Medium

EdWebServer.cs:189-191, 337-391, 418, 438-455

Android-only. Access-Control-Allow-Origin: * lets any page in the device browser call connect, disconnect, and data, putting raw telegrams on the bus. The cancellation source and listener subscription are locals, so Dispose never stops the listener.

E13. Lower-severity ENET items Low

  • EdInterfaceEnet.cs:4234-4350: TLS client certificate creation is under #if false, so S29Certs is always null and no client certificate is ever sent. EdBcTlsClient.cs:241 also requires rsa_sign although the keys are EC P-384. Delete or finish.
  • EdInterfaceEnet.cs:403-406, 485-486, 5035-5036: NmpParameter writes little-endian and reads big-endian; the NMP receiver appends six zero bytes to every payload.
  • Blanket catch (Exception) with no logging at lines 3471, 4722, 4793, 4919, 5465, 5536, 5663; ExtractSvrLocItems relies on IndexOutOfRangeException for bounds.
  • ReceiveEnetData checks recLen < 4 then reads index 5; SendEnetData and SendDoIpData copy dataLength bytes without checking sendData.Length, and a malformed request triggers up to three reconnects.
  • InterfaceLock has no callers anywhere, so the named mutex EdiabasLib_InterfaceEnet is created but never acquired.
  • InterfaceConnect(bool) is 525 lines, DetectedVehicles 447, the Ediabas setter 360 with about 40 near-identical config blocks, and the Nmt* wrappers repeat 930 lines of boilerplate.

OBD transport

Files: EdInterfaceObd.cs, EdInterfaceAds.cs, EdInterfaceEdic.cs, EdElmInterface.cs, EdElmWifiInterface.cs, EdCustomAdapterCommon.cs, EdCustomWiFiInterface.cs, EdBluetoothInterface.cs, BtLeGattSpp.cs, Ftd2xx.cs, EdInterfaceBase.cs.

O1. Malformed ISO-TP first frame crashes the process Critical

EdElmInterface.cs:396-412, 762-768

The first-frame length is taken from the adapter and used to allocate recDataBuffer, then five bytes are copied unconditionally. A length below five throws IndexOutOfRangeException on the ELM327 receive thread, which has no try block, so the exception terminates the process. Cheap adapters and bus glitches produce such frames.

Fix: validate telLen >= 5 and continue as the single-frame branch does; wrap the thread body in a try that logs and sets StreamFailure.

O2. All EdInterfaceObd transport state is static Critical

EdInterfaceObd.cs:103-122, 1289-1308, 2834-2856; EdBluetoothInterface.cs:21-43; EdCustomWiFiInterface.cs:43-64; EdElmWifiInterface.cs:26-37

SerialPort, the communication thread, its events, counters, and the mutex are static, while the thread function is an instance method bound to whichever instance started it. A second instance in the same process (one per API handle in ApiInternal, also inherited by EdInterfaceAds and EdInterfaceEdic) sees the thread as running, bumps the shared request counter, and waits for a thread that executes another object's protocol handler against another object's buffers. The three static helper classes share the same pattern with static Ediabas fields.

Fix: make the fields instance fields (the named mutex already provides cross-process exclusion), or enforce a single-instance invariant explicitly with EDIABAS_IFH_0018.

O3. Off-by-one length guards on CommParameter Medium

EdInterfaceObd.cs:533-761 (concepts 1, 2, 3, and 0x010D), 1654-1663, 1739-1748

Guards check Length < 7 but read index 7. The EDIC tester-present block tests ParTesterPresentTelLen instead of ParEdicTesterPresentTelLen and then copies from index 49 onward without bounding by the array length. An ECU file with exactly seven parameters surfaces as a raw IndexOutOfRangeException through Api32.dll.

Fix: change the guards to < 8, test the right field, and bound by Length - 49.

O4. Wire length not validated against the receive buffer Medium

EdInterfaceObd.cs:3988-3989, 4447-4459; EdInterfaceBase.cs:875-925

TelLengthBmwFast clamps to the buffer length, and the caller then requests one more byte than fits. The ISO-TP path ignores the 18-byte response offset, so Array.Copy throws for lengths between 2031 and 2048, and allocates up to 64 KB per frame. TelLengthBmwFast and DataLengthBmwFast index bytes 3 to 5 without a length check, which is reachable from simulation files.

Fix: explicit bounds checks that return EDIABAS_IFH_0009 after draining input; if (dataBuffer.Length < 4) return 0; in the helpers.

O5. SetDtrSignal swallows failures and returns success Medium

EdInterfaceObd.cs:3277-3302; callers 3646, 4852, 5473

Callers abort initialization with EDIABAS_IFH_0041 on false, but the method returns true from its catch, so an unplugged adapter proceeds into the 5-baud or fast-init sequence with the K-Line in the wrong state.

O6. CommParameter getter always returns null Medium

EdInterfaceObd.cs:356-366; EdInterfaceEnet.cs:1202; EdInterfaceBase.cs:44, 51-52, 76-81, 678

The base declares an auto-property; the overrides write CommParameterProtected and never call base, but the getter returns the never-assigned backing field. InterfaceMutex has a silent no-op setter, so the reassignment in InterfaceUnlock is discarded for subclasses that do not override it. BaudAuto is a mutable public static with a comment saying not to change it, and the BMW-FAST parameter arrays are mutable public statics.

O7. Busy-wait loops burn a core Medium

EdInterfaceObd.cs:3093-3095, 3150-3152, 3321-3345, 3381-3414

while (GetTimestamp() - start < wait) { } spins for the full byte time of a telegram, for example about 270 ms for a 256-byte KWP2000 telegram at 9600 baud, on every transmission. The 5-baud path already sleeps first and spins only the last 20 ms.

Fix: a PreciseDelay helper that sleeps coarsely and spins the last 1 to 2 ms.

O8. BLE timeouts are ignored and sync-over-async inside async code Medium

BtLeGattSpp.cs:180, 183, 423, 495

Task.Run(async () => await WriteAsync()).Wait(2000) discards the bool result, so a timed-out write returns normally with the bytes unsent and the caller waits the full protocol timeout for a reply. A faulted task later is unobserved. PairAsync().Wait() inside an async method blocks a pool thread and can deadlock under a synchronization context.

O9. Ftd2xx P/Invoke uses raw handles and copies uninitialized memory Medium

Ftd2xx.cs:197-343

No SafeHandle, so handles leak if a caller throws before FT_Close. FT_ReadWrapper copies bytesToRead bytes back even when fewer were returned, and there is no offset + count check. Per-call AllocHGlobal round-trips are unnecessary. The class is used only by EdiabasLibConfigTool, so it could move out of the runtime library.

O10. Lower-severity OBD items Low

  • Fields shared between the communication thread and callers (EcuConnected, RecBufferFrequentLength, BlockCounter, _elm327TerminateThread) are not volatile and rely on incidental fences.
  • Dead #if false blocks at EdInterfaceObd.cs:1933-1939, 5130-5136, EdElmInterface.cs:1063-1070, BtLeGattSpp.cs:357-379; while (cond) { return X; } used as if at four sites; 18 blanket catch (Exception) blocks that discard the exception text.
  • EdInterfaceBase.cs:455, 502: log format uses {0} twice, hiding the wake address.
  • 23 delegate types, 46 delegate fields, four near-identical 23-line hookup blocks, 23 property pairs, and three static classes re-implementing the same 20 entry points; six copies of the "signal comm thread and poll" loop.
  • Culture-sensitive StartsWith on port identifiers at EdInterfaceObd.cs:1358, 1384, 1410.
  • GetConfigProperty("RetryComm") parsed on every transmission from the communication thread.
  • IgnitionVoltage getter reconfigures the adapter to 115200 baud and switches the transmit function as a side effect.

Support, build, and tests

Files: EdSimFile.cs, IniFile.cs, MemoryStreamReader*.cs, MemoryQueueBufferStream.cs, EscapeStream*.cs, StreamExtension.cs, EdBase32.cs, Test/, EdiabasTest/.

S1. No runnable test path exists Critical

EdiabasTest/EdiabasTest.csproj:6, 16; Test/Scripts/coverage.bat:30, 40

The only test harness is EdiabasTest driven by coverage.bat against a car simulator, and neither builds since the .NET Framework targets were dropped. There are no unit tests. The repository's own guidance to "run coverage.bat" is stale.

Fix: retarget EdiabasTest, replace OpenCover with dotnet-coverage or coverlet, and add an xUnit project. See the roadmap for a concrete first test set.

S2. IniFile has no comment handling High

IniFile.cs:129-159; EdSimFile.cs:487-500

Lines starting with ; or # are parsed as keys. Inside a .sim file a commented request becomes key ;key1, which has no matching response, so the whole file is rejected with EDIABAS_IFH_0026. Standard EDIABAS files use ; comments.

Fix: skip lines whose first non-blank character is ; or #.

S3. Off-by-one in the simulation request-index operator High

EdSimFile.cs:323-328; EdInterfaceBase.cs:460-478

The guard is Count < operatorIndex, so operatorIndex == Count passes and the indexer throws ArgumentOutOfRangeException. Nothing catches it on the simulation path, so it escapes into the interpreter as a raw .NET exception instead of "no simulation data".

Fix: operatorIndex >= (uint)requestData.Count.

S4. Medium items Medium

  • EdSimFile.cs:70-93: DataItem.Equals ignores OperatorData and VarLength while GetHashCode includes them, so distinct requests such as 31,XX and 31,XX,.. merge into one round-robin entry.
  • MemoryStreamReaderCe.cs and EdSimInterface.cs are in no project and contain real bugs (wrong handle reset, wrong return count, unbounded index, throw ex). Delete them; git keeps history. MemoryStreamReaderAndroid.cs is live but duplicates about 70 percent of MemoryStreamReader.cs.
  • EscapeStreamReader.cs:213-239: IsDataAvailable waits on an event that only the reading thread sets, so it always sleeps the full timeout (2 seconds by default) when no data is buffered. Masked today because the Android Bluetooth path checks HasData() first.
  • MemoryStreamReader.cs:38, 168, 214-219: rejects seek-to-end, throws bare System.Exception, and fails on zero-length files with ArgumentException. Callers catch everything, so this surfaces as "file not found".
  • IniFile.cs:116, 218: reads UTF-8 while EDIABAS.INI and .sim files are Windows-1252, so a non-ASCII EcuPath is mangled.
  • MemoryQueueBufferStream.cs:87-90, 301-334 and EscapeStreamReader.cs:257-282: Read returns -1 on mutex timeout and after dispose; per-byte kernel mutex plus List.RemoveAt(0) makes reads quadratic.
  • StreamExtension.cs:39, 101-175: ReadBytesAsync spawns a thread per call, spins until timeout at EOF, and can leave an orphaned ReadAsync holding the caller's buffer; HasData() throws for non-seekable streams that are not special-cased.

S5. Low items Low

  • IniFile write support has no callers, bypasses the lock, clears the modified flag before writing, and replaces files non-atomically. Delete it or use File.Replace.
  • EdSimFile.ParseHexString silently drops a bare operator (01+) and truncates 0123 to 01 in responses while rejecting it in requests.
  • EdBase32.Decode throws IndexOutOfRangeException instead of FormatException for characters above 0xFF; EncodeByteString is unused.
  • coverage.bat:98, 101 writes results15.xml twice, losing one coverage run.
  • EdiabasLib.config:5 claims RetryComm is read from EDIABAS.INI; only five keys are.
  • MemoryStreamReader.cs:323-411: the directory cache with FileSystemWatcher only runs on the net9.0 build and watches subdirectories, which invalidates the cache on any change under a large ECU tree.

Strengths

  • Tight interpreter loop. Operands are reused, opcode dispatch is a direct table lookup, and per-opcode trace text is gated on a cached log level.
  • Disciplined culture and encoding handling. All parsing and formatting in the core uses the invariant culture and Windows-1252; no current-culture parsing was found in the opcode file.
  • Robust tracing. Named mutex, disposed checks, and rotating fallback files make the trace subsystem safe across processes, and the format matches EDIABAS for line-by-line diffs.
  • Timing done right. The OBD layer uses Stopwatch ticks with a precomputed resolution, honors the per-protocol W and P timing parameters, and keeps a dedicated communication thread alive for tester-present traffic.
  • Defensive frame parsing in ENET. Lengths are parsed into long and bounded before any cast or copy; acknowledgements are compared byte for byte; the DoIP inverse-version byte is checked; the SslStream path builds a real certificate chain.
  • Simulation engine. Culture-safe parsing, two-pass exact-then-wildcard matching, and round-robin multi-response support make the .sim format more capable than the original.
  • Structured errors. The fork's move to a top-level exception with an error code and argument dictionary, and messages from GetErrorDescription, is the right direction for hosts such as WsHub.

Suggested roadmap

  1. Unbreak the build and the WsHub integration (days). Fix F1, add the forwarding overloads from F3, switch WsHub to shared: false (E1) and plain port numbers (E8), and add a CI build for every target framework.
  2. Fix the crashers and packaging (days). O1, O3, O4, O5, S2, S3, C7, C8; delete both finalizers (E7); complete Directory.Build.targets for net10 and decide what net9.0 means (C3, C4); register the code page provider inside the library (C6).
  3. Add a unit test project (one to two weeks). xUnit on net10.0-windows10.0.26100.0 with a project reference. Cheap, hardware-free tests: EdSimFile parsing (standard and extended syntax, wildcards, operators, multi-response cycling, comment lines), IniFile (CRLF, whitespace, duplicates, culture, code page), FormatResult, StringToValue, StringToFloat, HexToByteArray (the -f cases in coverage.bat translate directly into theory rows), EdBase32 round trips, and EscapeStreamWriter to EscapeStreamReader round trips. Then convert the Test/Ecu .prg and .sim runs into golden-output tests, which gives CI coverage of the interpreter without a car simulator.
  4. Make the library instance-safe (weeks). Per-instance register table (C1), atomic JobRunning (C2), eager static tables (C5), per-instance transport state in EdInterfaceObd and EdInterfaceEnet (O2, E1), and receivers that flag rather than disconnect (E6).
  5. Harden the network layer. Dispose the client on connect timeout (E2), handle EOF in the receive pump (E3), PKIX validation in the BouncyCastle client (E4), a cancellation token through InterfaceConnect and TransmitData (E5), and protocol-error reconnects for oversized frames (E9).
  6. Reduce structural debt. Introduce an IObdTransport interface so the adapter helper classes become instances and the delegate plumbing disappears; introduce an IEnetFramer for HSFZ, DoIP, and NMP so the send and receive pairs collapse; split EdInterfaceObd.cs and EdiabasNet.cs into partial files by protocol and concern; collapse the Nmt* wrappers into one call helper; delete dead files and #if false blocks.
  7. Finish the error model. One constructor with a mandatory code (F2), one rethrow policy (F4), OperationCanceledException for aborts, InvalidOperationException for state errors (C9), typed argument keys, and a documented ownership rule for the interface handler.
